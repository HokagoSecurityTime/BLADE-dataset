# 통합 라벨 기준 v2.7 — 사람 검수 및 실험 운영

기준과 모델 프롬프트의 단일 원문은 [policy_label_v2.7.md](prompts/policy_label_v2.7.md)이다. 사람 검수도 동일 정의·근거 요건·복수 조건·보류 규칙을 적용한다. 별도 이름이었던 개발 기준 v1을 통합했으며 과거 문서는 당시 기록으로 보존한다.

## 이전 버전과의 관계

- v2.6과 보류 허용 실험본은 변경하지 않는다.
- 강제 구체 라벨 선택을 제거한다.
- ACL과 소유권, 인증과 역할, 협업 관계와 구독 자격을 구분한다.
- 조직 이름·project 경로만으로 tenant_match를 확정하지 않는다.
- 독립 필수 복합 조건을 단일 라벨로 왜곡하지 않는다.
- 근거와 판단을 구분한 rationale을 허용한다. 예전의 실제 값 나열만 허용하던 규칙을 대체한다.
- confidence만으로 사후 변환하지 않는다. 의미 라벨과 정책 집행 가능성을 분리한다.
- 기존 30개 few-shot은 새 기준 정합성을 보장할 수 없어 자동 이식하지 않는다. 따라서 향후 v2.6 비교는 “보류 문구 하나”의 효과가 아닌 통합 기준·예시 구성 변경 실험이다.

## 확정 검수 기록

`reports/eval/classification_quality/label_decisions_dev_v1_confirmed.jsonl`의 9건은 사용자 승인으로 모두 manual_review_required이며 v2.7과 일치한다. 과거 파일의 조건부·미확정 상태는 당시 기록이다. 원본 학습 라벨에 소급 적용하지 않는다.

## 새 100건 검수

`reports/eval/classification_quality/fresh_review_v1/review_100.md`의 선택 ID와 입력은 그대로 두고 이후 검수에는 v2.7 원문을 적용한다. 기존 파일은 보존한다. 아직 채워지지 않은 정답을 모델이나 에이전트가 대신 확정하지 않는다.

검수자는 제공된 입력만 보고 label과 사유를 작성한다. 외부 근거가 필요하면 별도로 표시하고, 그 근거가 모델 입력에도 포함됐는지 구분한다. 확정 전에 기준이 바뀐 항목은 버전을 기록한다.

## 측정

- 전체 7종 macro-F1, 사람 라벨 일치율, 보류율, 구체 선택률, 구체 선택 시 정확도를 함께 보고한다.
- 31건은 이미 분석한 오류 중심 진단 표본이며 독립 성능 추정에 쓰지 않는다.
- 100건은 기존 검수/분석 파일 ID와 중복 없이 선택했으나 이전 자동 라벨링 이력은 있다. 신호 유형별 표본이며 모집단 정확도 추정으로 일반화하지 않는다.
- 기준 변경으로 사람 정답이 바뀐 효과와 모델 판단 개선을 구분한다.
- 동일 입력·모델·프롬프트 해시·원시 응답·실제 사용량을 기록한다.

## 변경하지 않는 범위

runtime pipeline/proxy/admin_api, 루트 런타임 prompts/v2.0.md, AGENTS.md, 고정 test, 기존 라벨·선택 ID·검수 기록은 유지한다. v2.7 작성은 API 실행·전체 재라벨링·학습 승인이 아니다. 기존 라벨러가 자동으로 이 파일을 읽도록 설정을 변경하지 않았다. 다음 실험은 v2.7을 명시적으로 선택하고 별도 출력에 저장한다.
