# 통합 라벨 기준 v2.8 — 근거와 인가 경계

작성일: 2026-10-20

단일 기준 원문은 [policy_label_v2.8.md](prompts/policy_label_v2.8.md)이다. 기존 v2.7과 모든 실험 결과는 보존한다. v2.8은 설계 변경이며 성능 개선이 검증된 버전은 아니다.

## v2.7과의 차이

| 항목 | v2.7 | v2.8 |
|---|---|---|
| 판단 절차 | 정책 정의와 결정 흐름 | 대상·관계·조건·구현·출처를 먼저 확인 |
| 코드 미확보 | 별도 세분화 없음 | 코드 미확보, 부분 발췌 내 검사 미발견, 확인된 검사 누락을 구분 |
| 의도와 구현 | 의미 라벨과 집행 가능성 구분 | 의도된 정책의 근거와 구현된 검사를 추가로 구분 |
| 역할 혼동 | 인증·기능 scope와 역할 구분 | 관리자 소유 객체와 관리자 전용 기능도 구분 |
| 복합 조건 | 독립 필수 조건이면 보류 | AND/OR, tenant+owner 조건 확인 절차 명시 |
| 근거 설명 | 필드와 판단 이유 | 인접 라벨 배제 이유와 근거 수준 추가 |
| 취약점 분류 | 명시적 구분 없음 | BOLA 발생 유형·범위와 정책 라벨을 분리 |

7종 label, 네 가지 출력 필드, security_state 해석, mutation public 제한, confidence 사후 변환 금지, 예시 0건은 유지한다. 코드 입력을 의무화하지 않는다. OAS만 제공되면 그 입력에서 판단하며 코드를 보았다고 주장하지 않는다.

## 사람 검수 기록

새 코드 기반 표본은 아래 항목을 별도 검수 기록으로 남긴다. 모델 출력 스키마나 런타임 정책 스키마의 변경은 아니다.

| 항목 | 기록 내용 |
|---|---|
| 대상과 행위 | 해당 method가 실제로 다루는 객체·행위 |
| 관계 | 개인 소유 / 조직 일치 / 공유 ACL / 불명 |
| 요구 조건 | 인증·역할·구독·객체 조건과 AND/OR |
| 의도 근거 | 명세·테스트·문서의 실제 정책 근거 또는 미확보 |
| 구현 근거 | 핸들러·미들웨어·서비스 계층의 파일:줄, 저장소 커밋 |
| 확인 범위 | 검사 확인 / 부분 발췌에서 미발견 / 확인 범위 내 누락 / 코드 미확보 |
| 판단 | 제안 label, 선택 및 인접 라벨 배제 이유 |
| 사람 확정 | 확정 label·사유·검수자·일시; 검수 전 빈칸 |

검사 미발견만으로 취약성을 확정하지 않는다. 코드에서 확인한 사실과 의도에 대한 추론을 구분한다. 복합 조건·ACL·근거 부족은 보류 이유를 구분해 기록하되 새 정책 label은 만들지 않는다.

## 적용 및 평가

- 라벨 생성은 기존 승인된 API 호출 방식과 BLADE_LABEL_* 설정을 사용한다. 에이전트가 학습 정답을 대신 확정하지 않는다.
- 실행 시 v2.8 파일을 명시적으로 선택하고 원시 응답·모델·입력 및 프롬프트 해시·사용량을 기록한다. 기존 실행기의 버전 기본값은 바꾸지 않는다.
- 모델 입력에서 사람 정답·제안 라벨·이전 예측·검수 사유를 제외한다. 코드 근거를 description에 담을 때에는 실제 소스와 출처만 전달한다.
- OAS만 입력한 조건과 OAS+코드 조건은 같은 ID·모델·프롬프트로 비교한다. 코드 조건에서 보이는 근거와 OAS만으로 판정 가능한 범위를 별도로 기록한다.
- 정답 정책 일치율, macro-F1, 보류율, 구체 선택 정확도와 함께 입력만으로 정책을 판별할 수 있었는지 보고한다. 코드 기반 정답을 OAS만으로 못 맞힌 사례를 곧바로 모델 능력 부족으로 단정하지 않는다.
- 서비스와 동일 구현 계열을 분할 단위로 삼는다. RealWorld의 동일 기능 구현체 등을 서로 독립적인 도메인으로 계산하지 않는다.
- 사람 확정 전 정확도 개선을 주장하지 않는다. 기존 100건은 사람 정답이 미확정이며 v2.8 생성으로 확정되지 않는다.

이번 변경은 새 프롬프트·기준 파일 생성만이다. API 실행, 데이터 수집, 전체 재라벨링, 학습은 수행하지 않는다. 기존 프롬프트·라벨·보고서·고정 test·런타임 코드는 변경하지 않는다.
